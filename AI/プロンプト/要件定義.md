# Phase 1：要件定義

```md
今回の目的はWebアプリの要件定義です。

まだ実装はしないでください。

# 作りたいもの

1. 応用情報技術者試験では、数学、アルゴリズム、データベース、ネットワーク、セキュリティなど、文章や静的な図だけでは直感的に理解しにくい知識・理論が出題される。

2. ユーザー自身が値や条件を入力し、その入力に応じて処理結果や状態変化を画面上で可視化することで、知識・理論を体験的に理解できるようにしたい。

3. 単に解説を読む教材ではなく、
   「入力 → 処理・状態変化の可視化 → 結果 → そこから何が分かるか」
   を一連の流れとして体験できるWebアプリを作りたい。

4. 個別の可視化教材は後から1つずつ追加できる構成にしたい。

# 想定ユーザー

応用情報技術者試験を学習しているIT業界従事者のうち、試験で扱われる各専門分野について十分な専門知識を持っていないユーザーを主な対象とする。

# 解決したい課題

・応用情報技術者試験で登場する知識や理論について、文章による説明だけでは処理の流れや概念を直感的に理解しにくい。

・計算結果やアルゴリズムの途中状態などを自分で操作しながら確認できる教材がないと、知識を暗記するだけになりやすい。

・ユーザー自身の入力に応じて結果や状態変化を可視化し、「なぜその結果になるのか」「その結果から何が言えるのか」を確認できることで、理解を促進したい。

# 必要だと考えている機能

・ログイン・ログアウト機能

・HOME画面

・分野別学習一覧画面

・個別分野学習画面

・学習履歴画面

個別分野学習画面については、数学、アルゴリズム、データベース、ネットワーク、セキュリティなどの教材を将来的に追加していく。

ただしMVPでは、すべての分野を実装せず、代表的な可視化教材を必要最小限だけ実装する想定とする。

# 技術上の条件

・ローカルで開発できること

・低コストでWeb公開できること

・スマートフォンで利用できること

・将来的な機能追加がしやすいこと

・個別の可視化教材を既存機能への影響を抑えて追加できること

# 確認してほしいこと

・MVPとして大きすぎないか

・不要な機能がないか

・MVPで実装すべき個別教材はいくつが適切か

・ログイン・ログアウト機能はMVPに必要か

・学習履歴機能はMVPに必要か

・機能ごとの責務が明確か

・個別の可視化教材を後から追加しやすい要件になっているか

・将来的な拡張を妨げる要件がないか

・要件として不足している項目がないか

・曖昧な点や設計に影響する疑問点がある場合は、勝手に仮定せずこちらに質問すること

# 完了条件

□ MVPが定義されている

□ MVPで実装する個別教材の範囲が決まっている

□ 機能一覧が決まっている

□ 画面一覧が決まっている

□ 画面遷移が決まっている

□ 各画面・機能の責務が決まっている

□ MVP対象外が明確になっている

□ 将来的に追加する機能がMVPと分離されている

最後に、確定した要件をMarkdown形式でまとめてください。

ただし、確認が必要な事項が残っている場合は、要件を確定扱いにせず、先に質問事項を提示してください。
```
